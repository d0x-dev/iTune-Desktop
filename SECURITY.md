# Security policy

## Supported versions

Security fixes are made against the latest source on the default branch. Update to the latest desktop release before reporting an issue when possible.

## Report a vulnerability privately

Please do not disclose suspected vulnerabilities in a public issue, discussion, or pull request. Use GitHub's **Report a vulnerability** action in the repository Security tab when available. If private vulnerability reporting is unavailable, contact the repository owner privately through GitHub.

Include the affected app version, operating system and version, impact, reproduction steps, and sanitized logs or proof of concept. Do not include passwords, session cookies, account tokens, private backups, or another person's data.

## Secret handling

Never commit signing keys, credentials, API tokens, account cookies, backup files, or private user data. If a secret was committed, revoke or rotate it; removing it later does not make it safe.
